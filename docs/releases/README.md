# DartFlow-releases

De productversie volgt `major.minor.patch`. Web/desktop en Android Player krijgen voor gedeelde productwijzigingen dezelfde productversie. Android gebruikt daarnaast een strikt oplopende `versionCode`. Oche Live heeft een eigen productversie en Android-code; een controle van Oche Live is geen bewijs van een nieuwe Play-publicatie.

| Versie | Android Player | Status | Samenvatting |
| --- | --- | --- | --- |
| [0.6.1](0.6.1.md) | code 10 | Implementatie en verificatie | Schermvullende scorebediening voor vrije partijen, oefeningen en wedstrijden; leesbare pijlknoppen |
| [0.6.0](0.6.0.md) | code 9 | Staging/productie geaccepteerd; Player intern/productie code9 `completed` | Privésupport, releasebeheer, klikbare inbox, kanaalregels, browserpush en gecontroleerde campagnes |
| [0.5.0](0.5.0.md) | code 8 | Web/Player uitgegeven; Oche 1.4.0 GitHub geleverd, Play geblokkeerd | Clubhouse, premium huisstijl, interne competitiewizard, veegscrollen en aanklikbare schakellabels |
| [0.4.0](0.4.0.md) | code 7 | Uitgegeven | Speleridentiteit, uitnodigingen/QR, spelen, meldingen en Firebase-koppeling |

Gebruik voor elke volgende uitgifte [TEMPLATE.md](TEMPLATE.md). Kopieer het bestand naar `<versie>.md` en voeg een rij aan deze index toe. Schrijf vóór publicatie wat verandert en welke bewijzen vereist zijn. Vul uitgiftegegevens pas in na controle van de werkelijk uitgerolde commit, configuratie, ondertekende bestanden en distributietrack. Bewaar mislukte pogingen als historie; vervang ze niet door een uitslag van een andere poging.

Een geslaagde build, een upload naar Google Play en een beschikbare winkelupdate zijn verschillende statussen. Noteer ze afzonderlijk. Deel geen privésleutels, tokens, pincodes, persoonlijke agenda-abonnementen of gegevens van leden in releasedocumentatie.
